# 归档方法论与算法说明

> 本文件是 archive-organizer 的设计依据，由真实项目归档实战沉淀而来；只写通用机制，不收录任何特定项目的关键词。

## 1. 三层结构

| 层级 | 含义 | 确定方式 |
|------|------|----------|
| 一级目录 | 业务域（如「合同与造价」「标准规范」） | 沿用现有顶层目录名，不重命名 |
| 二级业务类型 | 该域应涵盖的业务类型集合 | 脚本按目录名关键词聚类推荐 → 人工校验 |
| 三级通用文件标准 | 由二级集合聚合出的通用文件形态 | 聚合去重；已落具体域的形态不进通用集 |

## 2. 关键规则（会话共识，适用于任何项目）

1. **扁平优先，标签为主**：文件夹只划层级、不堆内容；相同性质文件靠标签压平（如 `[报公司]`、`[202603]`）。
2. **不增层**：合并/拆分不得新建嵌套目录，只能在已存在的同级域内收口。
3. **二级→三级必须明确**：每个二级对应一组确定的通用文件形态，无歧义。
4. **三级去重/边界排除**：已落位到具体二级域的形态（如「结算审核表」），不进最通用集。
5. **深度提取是最后手段**：能用文件名/目录名判断的，绝不读正文。

## 3. 三层判断逻辑

```
第1层 域级结构判断：二级数量≤--max-calm 视为已合理（锚定行）；否则出收口建议
第2层 同级内容收口：二级名+文件名即可判断的，同类原地归并（不增层）
第3层 深度内容提取：名字判不了才读正文（ao_deep.py），极少数
```

## 4. 算法说明

### 4.1 关键词聚类提示（ao_schema.py）

目标：从一堆二级目录名里发现「该按什么主题合并」。借鉴 TF 关键词聚合思想：

1. 每个目录名去掉数字序号前缀（`6.`、`01-` 等），提取连续汉字段/字母数字段（≥2字）作为候选词；
2. 统计每个候选词「出现在多少个目录名中」（子串包含匹配，容忍 `物资材料` 命中 `物资材料汇总`）;
3. 长词优先保留：候选词若已被某个更长且已保留的词完全覆盖则丢弃，避免 `通知` 淹没 `经济活动分析会的通知`；但若短词能覆盖长词覆盖不到的新成员，仍保留（`合同` 与 `总承包合同` 并存）;
4. 出现在 ≥2 个名称中的词按覆盖数降序输出为「聚类提示」。

### 4.2 规则化移动（ao_classify.py）

移动只做三种原子操作（并目录/移目录/移文件），复杂调整由人或模型拆解成规则序列。
安全性设计（每一条都是旧版踩过的坑）：

- **默认干跑**：不加 `--execute` 只打印将发生什么（旧版 `classify_files.py` 一跑就真移动）；
- **路径锚定 root**：所有规则路径相对 `--root` 解析，并做 `commonpath` 越界校验（旧版把文件移到了进程当前目录）;
- **禁止目标落入源内部**：防止把目录搬进自己造成的递归灾难;
- **重名加 ` (n)` 序号**：绝不静默覆盖（rclone/Finder 行为）;
- **移动日志 journal**：每条移动以 JSONL 落盘，`--undo` 逆序回放即整体回滚;
- **只清真空壳**：只删除「确实搬空了文件」的源目录残留，用户原有的空目录不动。

### 4.3 规则体检（ao_verify.py）

`移文件` 是全根子串捞取，误捞代价高且静默。体检脚本在**不移动任何文件**的前提下，
用「规则 + 目录现状」推导出全部风险信号（不含任何项目词）：

- **零命中**：根内没有任何文件名含该词 → 关键词过时/过窄（错误级）；
- **全部已在目标**：命中文件均已位于目标目录 → 规则已完成，可从 CSV 移除（知悉）；
- **跨域命中**：命中文件横跨多个一级域 → 若非有意归拢即误捞（警告）；
- **宽泛词**：关键词过短或命中数超阈值 → 拆成文件名中独特的词组串（警告）；
- **跨域同名疑似镜像**：同一文件名出现在多个域的平行目录树下 → 整树镜像副本信号，
  先由用户裁决以哪份为准，不对镜像对写规则（警告）；
- **规则重叠**：同一文件被多条移文件规则命中 → 先到先得，后面的规则少移（知悉）；
- **压平捞取**：移文件规则排在目录规则之前时，会把目录规则源树内的命中文件
  压平捞走 → 想保留结构就把目录规则排前面（知悉）；
- **收口重名**：并目录源树与目标已有文件同名 → 将加 ` (n)` 序号（知悉）。

纪律闭环：**verify 预计移动数 = classify 干跑计数**，两边对不上说明规则或状态有问题，
先查再谈执行。执行后出现的「跳过已消失」要逐条对账，通常是规则重叠被先到者裁决。

### 4.4 忽略规则（ao_common.Excludes）

借鉴 rsync 的 exclude 机制。内置默认：隐藏目录一律跳过；`.DS_Store`、`Thumbs.db`、`desktop.ini`、macOS AppleDouble（`._*`）、Office 锁文件（`~$*`）不进清单。`--exclude` 追加（精确名或通配模式），`--no-default-excludes` 全关。

### 4.4 位置快照：人工调整保护与增量检测（ao_state.py）

以「相对路径: 大小」记录全树基线，classify 执行成功后自动刷新。两次基线之间的
差异全部来自人工操作，据此三分：

- **移位/改名**（基线有 P、现状在 Q 且 同名同大小）→ 人工调整。写入人工保护
  清单（文件名+大小为键），collect 与 verify 一律跳过——**人工调整永不回改**；
- **新增**（基线完全不存在）→ 待归档增量，供下轮拟规则；
- **消失** → 外部删除，只报告不复活。

### 4.5 归档目录保护（ao_protect.py）

工作目录「归档整理/」平时隐藏+锁定：macOS `chflags hidden` + 递归 `uchg`；
Windows `attrib +h` + 递归 `+r`（建议性只读）。锁定状态与受锁条目清单写在
工作目录内 `.ao_lock.json`，解锁按清单逐一恢复。其余脚本写入产物前自动解锁、
结束自动恢复，对使用者透明。

### 4.6 语义错位探测（ao_semantic.py）

错位文件的「语义」不靠词表硬编码，靠**域画像的分布**推导：

1. 每个一级域统计「二级目录名+文件名」词元的文件覆盖数；
2. 词元区分度 w(词,域) = 域内覆盖数 ÷ 全域覆盖数——各域都用的词（通知/表）
   权重趋零；同一词在 A 域是主角、在 B 域是配角，区分度自然拉开，这正是
   细微语义差异（同名不同义）的分辨机制；
3. 文件按其文件名词元对各域求和打分，他域显著高于本域（margin + min-diff
   双阈值）即错位候选，输出 CSV **供人审**，确认后翻译成规则执行。

### 4.7 内容提取回退链（ao_deep.py）

- docx/xlsx：zip 内 XML 正则（word/document.xml、xl/sharedStrings.xml）
- pptx：遍历 **zip 成员列表** `z.namelist()`（旧版误用文件系统 glob，永远读空——已修）
- pdf：`pdftotext` 命令 → `pypdf` 库 依次回退；都不可用则报大小跳过
- 提取结果经 XML 实体还原（`&amp;` 等）+ 空白折叠

## 5. 开源借鉴一览

| 借鉴来源 | 拿来的做法 |
|---|---|
| [organize](https://github.com/ThomasWaldmann/organize)（文件整理工具） | 默认干跑、执行写 journal、支持 undo |
| rclone / macOS Finder | 目标重名自动 ` (n)` 序号，绝不覆盖 |
| rsync / fdupes | exclude 过滤垃圾文件的模式 |
| TF 关键词聚合 | 目录名聚类提示的词频思想 |

## 6. 一次完整会话的标准动作（可直接照抄）

```bash
S=~/.agents/skills/archive-organizer/scripts
ROOT=/path/to/项目            # 所有产物自动落在 $ROOT/归档整理/ 下
# ① 扫描（只读）
python3 $S/ao_scan.py --root "$ROOT"
# ② 骨架评审CSV（不移动）→ 交用户逐行勾「是否调整」
python3 $S/ao_schema.py --root "$ROOT"
# ③ （仅当名字看不出性质时）深挖采样
python3 $S/ao_deep.py --root "$ROOT" --domain "某域" --limit 10
# ④ 把人审结论写进 $ROOT/归档整理/归档规则.csv
# ⑤ 规则体检（只读）：错误必须清零，警告逐条给出理由
python3 $S/ao_verify.py --root "$ROOT"
# ⑥ 干跑预览，计数须与体检一致
python3 $S/ao_classify.py --root "$ROOT"
# ⑦ 用户确认后执行；后悔则 --undo
python3 $S/ao_classify.py --root "$ROOT" --execute
python3 $S/ao_classify.py --root "$ROOT" --undo
```

## 7. 骨架重排（换分类体系）的映射回放法（ao_remap.py + ao_replay.py）

当关键词规则表达不了重排（同名文件不同去向、跨域语义重划、逐文件定路径）时，改走
「规则数据 → 逐文件映射表 → 回放执行」三段式。机制在技能，关键词在项目的
`骨架重排规则.csv`，互不掺和——换机器/换项目只带规则 CSV。

- `移树` 子树整树移植（最长前缀优先）：结构语义完好的目录原样搬，是决策量的主力压缩器；
- `归槽` 散件按名归槽（作用域最长优先，行序即裁决序）：只对未被移树覆盖的散件生效；
- `留守` 垃圾跳过。产出 `映射总表.csv`（一行一文件）+ 未决清单 + 归槽审计 + 流量矩阵。

### 实战教训（已固化进工具守卫，写规则时仍须自知）

1. **归槽目标必须拼文件名**：把目录槽当文件目标回放，首个文件会被重命名成目录名。
   ao_remap 自动拼接；ao_replay 预检对「≥3 行共享同一目标」直接拒绝（≤2 行视为版本件共存）。
2. **枚举齐目录再写移树**：漏掉一个子目录的移树行，它的文件会悄悄落到归槽兜底——
   归槽审计按目录聚合计数，裸奔目录一眼可见，生成后必须逐条过目。
3. **文件名归一化再匹配**：带空格/全半角变体的名字（如「承 诺 函」）会咬不中关键词，
   归槽匹配前自动去空白归一。
4. **兜底行放该作用域最后一行**，且只是安全网；未决数必须为 0 才能进回放。
5. **终验三件事**：文件总数守恒（执行前后一致）、流量矩阵与设计稿对账、旧目录壳只剩留守垃圾。
6. **日志全程兼容** `ao_classify --undo`，多轮整理叠加后回滚会自动跳过已失效的条目。
7. **与既有机制互通**：replay 执行后自动刷新位置基线（否则下次 diff 会把整轮移动误报为
   人工调整、污染保护清单）；映射含人工保护文件时预检知悉提示（映射是整体已审方案，
   remap 从现树生成、人工调整后的现位置即映射源，故不阻断）；工作目录锁定态自动解锁/回锁。
8. **预检错误分级**：hard（源缺失/重复/越界/垃圾/非法路径）任何参数都不可放行；
   shared（≥3 行共享同一目标=目录槽事故嫌疑）仅 --allow-shared-dst 豁免——两 类绝不混在
   一个开关里，否则豁免开关会变成总闸。
9. **批次化与终验**：每条日志带 batch 号；--undo-last 只回滚最近一批、--list-batches 查看；
   执行后打印前后文件总数守恒结论，计数不闭环就是出了事。
